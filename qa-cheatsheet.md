# QA Automation — Шпаргалка

Краткий рабочий конспект по обучению QA → QA Automation.

## 1. SDLC — Software Development Life Cycle

**SDLC** — жизненный цикл разработки программного обеспечения.

Типовая схема:

`Идея → Требования → Проектирование → Разработка → Тестирование → Релиз → Поддержка`

Важно:
- этапы не обязательно идут строго линейно;
- могут пересекаться и повторяться;
- тестирование может происходить на разных этапах SDLC.

Ключевые термины:
- **SRS (Software Requirements Specification)** — документ с требованиями к ПО.
- **UAT (User Acceptance Testing)** — проверка продукта с точки зрения принятия пользователем/заказчиком.
- **Production / Prod** — рабочая среда, где используется реальный продукт.

## 2. STLC — Software Testing Life Cycle

**STLC** — жизненный цикл процесса тестирования.

Основные этапы:

`Requirement Analysis → Test Planning → Test Case Development → Test Environment Setup → Test Execution → Test Cycle Closure`

Разница:
- **SDLC** — жизненный цикл всего продукта.
- **STLC** — жизненный цикл тестирования.
- Они пересекаются во времени.

## 3. 7 принципов тестирования

### 1. Testing shows presence of defects
Тестирование может показать наличие дефектов, но не доказать их отсутствие.

### 2. Exhaustive testing is impossible
Невозможно проверить все комбинации данных, действий, окружений и состояний системы.

Поэтому выбирают важные и рискованные сценарии и используют техники тест-дизайна.

### 3. Early testing
Чем раньше обнаружен дефект, тем проще и дешевле его исправить.

### 4. Defect clustering
Дефекты часто концентрируются в небольшом количестве компонентов или областей системы.

### 5. Pesticide paradox
Если постоянно выполнять одни и те же тесты, со временем они перестают находить новые дефекты.

Тесты нужно пересматривать, обновлять и дополнять.

### 6. Testing is context dependent
Тестирование зависит от конкретного продукта, его требований, рисков и контекста.

### 7. Absence-of-errors fallacy
Отсутствие найденных ошибок не означает автоматически, что продукт хороший или полезный.

## 4. QA / QC / Testing

### QA — Quality Assurance
**Обеспечение качества.**

Фокус: **процесс**.

QA направлено на обеспечение выполнения требований к качеству и предотвращение проблем.

`QA = process + prevention`

### QC — Quality Control
**Контроль качества.**

Фокус: **продукт / результат**.

QC включает действия по оценке качества компонента или системы.

`QC = product + control`

### Testing
**Тестирование** — конкретные проверки программного продукта/системы для оценки качества и выявления дефектов.

В рассматриваемой модели:

`Testing ⊂ QC`

То есть тестирование является частью контроля качества.

### Главное различие

| | QA | QC | Testing |
|---|---|---|---|
| Фокус | Процесс | Продукт | Проверки продукта |
| Основная идея | Предотвращать проблемы | Контролировать результат | Находить дефекты / проверять соответствие |

**QA → предотвращаем**

**QC → контролируем результат**

**Testing → непосредственно проверяем**

## Как использовать шпаргалку

Не нужно заучивать формулировки дословно.

Цель:
1. объяснить термин своими словами;
2. привести простой пример;
3. отличить похожие понятия;
4. применить концепцию к реальному тестированию.

Новые темы добавляются сюда по мере прохождения обучения.
